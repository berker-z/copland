Copland box @VERSION@, Linux @ARCH@

  bin/copland-box      a window on the daemon (GPUI)
  bin/copland-daemon   the same daemon, headless
  bin/copland-tray     the daemon in your bar's system tray
  share/               the launcher entries, the icon and the daemon's
                       systemd user unit

The layout matches ~/.local, so installing for yourself is one copy:

  cp -r --remove-destination bin share ~/.local/
  gtk-update-icon-cache -f -t ~/.local/share/icons/hicolor 2>/dev/null || true

That puts the binaries in ~/.local/bin, copland-box.desktop and
copland-tray.desktop in ~/.local/share/applications and the icon in
~/.local/share/icons/hicolor/{scalable,32x32,...,256x256}/apps. The launcher
runs `copland-box` from PATH; if ~/.local/bin isn't on your desktop
session's PATH, change Exec= in the desktop file to the full path.

Run the copy in ~/.local/bin, not the one in this directory: the service
and the entries that start the box and the tray at login name the binary
by its path, and they refuse a path like this one (a folder named for one
version, ~/Downloads, /tmp), which won't be there after the next upgrade.

To upgrade, copy the newer tarball's bin and share over ~/.local the same
way (--remove-destination, since the daemon's binary is in use), then
`systemctl --user restart copland-daemon`. The service keeps the same
unit; `copland-daemon --check` says when the daemon running is older than
the binary on disk.

Then start `copland-box`. Without a config it sets itself up in its window:
type your Copland's address and approve the box in the browser. Setup ends
by installing the daemon as a systemd user service (the copland-daemon next
to the box), which runs your agents from then on, at every login, whether
the box is open or not. Whenever no daemon is running, the box offers to
install or start the service, or to run one until you log out.
`copland-box --demo` shows the scene without a server.

copland-tray shows whether your agents are idle, working or need you, can
hold an agent or stop a run, and opens the box. Turn it on at login in the
box (menu › settings › tray at login), or answer yes when
`copland-daemon --setup` asks. It needs a bar or panel with a
StatusNotifierItem tray: KDE Plasma, waybar, and most others do; GNOME
needs the AppIndicator extension. Quitting it leaves the daemon running.

Upgrading from 0.4.x, where the box ran the agents itself and closing it
stopped them: the first start says so once and offers the service.

On a machine with no display, run the headless daemon as a service:

  copland-daemon --setup              # approve it in Copland, pick runtimes
  copland-daemon --install-service    # a systemd user unit, enabled and started
  journalctl --user -u copland-daemon -f

--install-service writes ~/.config/systemd/user/copland-daemon.service for
this binary and config, from ~/.local/bin or another place that lasts
(it says how to get there otherwise). Running it again leaves an
unchanged unit alone and replaces one that runs a binary since moved. The daemon finds the runtimes when it starts, on
its PATH, your login shell's and ~/.local/bin; --check shows where.
On a server you aren't logged in to, `sudo loginctl enable-linger $USER`
keeps it running. share/systemd/user/copland-daemon.service is the same
unit for ~/.local/bin, to install by hand instead.
`copland-daemon --uninstall-service` stops and removes it.

What it needs:

  - glibc @GLIBC@ or newer (built on Ubuntu 24.04).
  - For the window: libxcb, libxkbcommon and libxkbcommon-x11 (linked), and
    the Vulkan loader with a Vulkan driver, libwayland-client and
    fontconfig (loaded at run time). On Debian and Ubuntu:
      sudo apt install libxkbcommon-x11-0 libvulkan1 mesa-vulkan-drivers \
        libwayland-client0 libfontconfig1
    Most desktops have all of these already.
  - copland-daemon needs nothing beyond glibc to start.
  - Coding runs (an agent with a code_command) need bubblewrap, from your
    distribution: the bubblewrap package on Arch, Debian, Ubuntu and
    Fedora (pacman -S bubblewrap, sudo apt install bubblewrap, sudo dnf
    install bubblewrap). Use that one, not a bwrap of your own: on Ubuntu
    24.04 and later AppArmor lets only the distribution's /usr/bin/bwrap
    make the user namespaces it needs. Without a working bwrap coding runs
    wait, and the box says why.

These binaries are not signed. Check them against SHA256SUMS on the release
page. On NixOS use the flake instead (daemon/README.md): a plain binary
won't find the libraries there. There, the flake's home-manager module
(services.copland) runs the daemon and the tray as user services; a
copland-daemon from the Nix store writes no unit of its own and prints the
module to add when asked to --install-service.
