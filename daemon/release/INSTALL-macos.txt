Copland box @VERSION@, macOS Apple Silicon

  copland-box      a window on the daemon (GPUI, Metal)
  copland-daemon   the same daemon, headless

The window is easier to use as Copland.app, from the .zip next to this
archive on the release page. These are the same binaries for a terminal:

  mkdir -p ~/.local/bin && cp copland-box copland-daemon ~/.local/bin/
  xattr -d com.apple.quarantine ~/.local/bin/copland-box ~/.local/bin/copland-daemon

They are not signed or notarized, so macOS refuses them until the
quarantine flag is removed as above (only needed when a browser downloaded
the archive). Check them against SHA256SUMS on the release page first.

Started without a config, the box sets itself up in its window and ends by
installing the daemon as a launchd agent (the copland-daemon next to it),
which runs your agents at every login, whether the box is open or not.
Whenever no daemon is running, the box offers to install or start it, or to
run one until you log out. A box upgraded from 0.4.x, which ran the agents
itself, says so once and offers the agent.

To run the headless daemon without the window, at every login:

  copland-daemon --setup              # approve it in Copland, pick runtimes
  copland-daemon --install-service    # a launchd agent, loaded and started

That writes ~/Library/LaunchAgents/dev.berkerz.copland.daemon.plist for
this binary and config, and logs to ~/Library/Logs/copland-daemon.log.
The agent runs the binary from where it is, so it has to stay there:
~/.local/bin as above, or Copland.app in /Applications. One run from this
archive's folder, Downloads, a disk image or a temporary folder is refused,
with the command that copies it somewhere that lasts. Running it again
leaves the agent as it is, or points it at the binary it was run from. The daemon finds the
runtimes when it starts, on its PATH, your login shell's, ~/.local/bin and
/opt/homebrew/bin; --check shows where.
dev.berkerz.copland.daemon.plist here is the same agent as a template
(@DAEMON@ and @LOG@ are absolute paths), to install by hand instead.
`copland-daemon --uninstall-service` stops and removes it.

Built on macOS 14 for macOS 11 and later. Not yet tried on real hardware.

Coding runs are sandboxed with Seatbelt (/usr/bin/sandbox-exec), which
macOS has built in: nothing to install. CI checks that sandbox on macOS 14;
nobody has on a real Mac yet.

Docs: https://github.com/berker-z/copland/blob/main/daemon/README.md
